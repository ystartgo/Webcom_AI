什麼是 Artifact？獨立預覽沙箱

當要求 AI 產出完整的單檔網頁 (HTML/CSS/JS)、SVG 向量圖形、Markdown 報告或腳本時，AI 會以 <artifact> 標籤包裹輸出。系統會在對話框即時呈現高質感互動卡片，具備安全隔離沙箱 (iframe Sandbox)，免佈署、免伺服器即可直接在本機運行與互動！

多段智慧接續與無縫縫合 (避免字數上限中斷)

長程式碼（如 500+ 行應用）常因大語言模型單次輸出 Token 限制而被硬性打斷。Webcom 具備自動重疊去重縫合演算法：

  • 同名識別：後續輸出帶有相同 identifier 與 mode="continue" 時，系統自動定位主檔案。
  • 智能去重：自動比對前段結尾與後段開頭 1~25 行重疊部分及字元滑動去重，剔除重複行無縫拼接。
  • 緊湊接續卡片：後續對話以輕量卡片呈現「已自動接續合併至【標題】（新增 +X 行，總計 Y 行）」，拒絕冗餘刷屏。
  • 一鍵接續按鈕：若偵測到未完結，卡片底部直接提供「▶️ 一鍵接續生成 (Continue)」，自動引導 AI 輸出下一段。

什麼是 Jev？(System 1 非生成式極速決策)

Single Forward Pass

Jev 是專為「意圖分類、工具路由、安全護欄、故障分流」打造的快思 (System 1) 交叉編碼決策器。 傳統大語言模型（如 GPT、Claude、Qwen）採用逐字自回歸生成 (Autoregressive Token Loop)，即使僅需輸出一個選項名稱，也必須經歷數百毫秒的逐步解碼並消耗大量記憶體與電力；而 Jev 採用單次前向傳遞 (Single Forward Pass, SFP)，以常數時間複雜度直接計算輸入語句與所有候選選項（Candidates）的交互注意力相關性，徹底繞過生成迴圈。

1. ~15ms 毫秒級極致延遲 (加速 100~200x)

在一般輕薄筆電 CPU 或內建顯示卡即可達成 15ms~30ms 極速推論，相較生成式大模型加速 100 至 200 倍，使用者毫無等待感知。

2. 100% 嚴格封閉機率空間 (零幻覺)

所有候選選項輸出經由 Softmax 嚴格歸一化（Σ Pi = 100%），結果必然落在預設選項內，絕無 JSON 格式錯誤、多餘廢話或幻覺指令。

3. 溫度動態校準控制 (T ∈ [0.1, 2.0])

支援動態溫度調整：低溫（T=0.2）輸出尖銳確定解，高溫（T=1.5）平滑機率分布以探索邊緣意圖，並提供熵值（Entropy）作為信心指標。

4. 超輕量資源佔用 (22MB ~ 140MB)

模型體積僅 22MB~140MB，記憶體佔用小於 200MB，完全無需獨立顯卡，在 WinPE 無網維護環境或邊緣嵌入式設備皆能流暢運作。

最佳實踐：1+1 雙引擎協同架構 (快思 + 慢想)

Webcom 推薦的架構模式為「Jev 負責 15ms 快思篩選，大模型負責深度慢想」：

  1. 前端過濾：使用者輸入任何指令時，先經由 Jev 進行 15ms 的意圖識別與安全檢查。
  2. 極速繞道：若意圖為終端執行（如 dir, ls）或串口控制，直接分流執行，完全無須喚醒肥大模型。
  3. 深度委派：僅當 Jev 識別為「需要寫作或深度邏輯解答」時，才喚醒後端生成式 LLM。既省算力又使整體系統反應速度提升數倍！
如何立即體驗 Jev 決策沙盒？

點擊頂部工具列上的 ⚡ Jev 決策器 膠囊按鈕，即可隨時開啟互動測試沙盒，即時體驗 15ms 的極速決策！

3. TCP/IP: SSH 與 Telnet 遠端連線

設定遠端伺服器或路由器 IP、Port、帳號密碼後點擊「套用連線」，AI Agent 能透過後端 Daemon 自動發送 SSH / Telnet 指令進行遠端設備維護。

Q1: LM Studio 提示 Failed to fetch / CORS 錯誤？

A: LM Studio 需允許跨域存取。請在終端機啟動：lms server start --cors --port 1234，或在 LM Studio 本地伺服器面板勾選 Enable CORS。亦可直接切換至「⚡ WebGPU 瀏覽器純本機」模式。

Q2: 常駐程式 (Port 8001) 連不上或被舊進程佔用？

A: 點擊頂部「常駐程式狀態」開啟面板，點擊 `[確認一鍵重啟 / 啟用]`，系統會自動強制終止佔用 8001 端口的舊行程並重新乾淨拉起服務。

Q3: WebGPU 模型下載進度與顯卡支援？

A: 首次使用 WebGPU 模型（如 Qwen2.5-0.5B 約 350MB）會自動下載並永久快取在瀏覽器中。支援 Chrome 113+ / Edge 等支援 WebGPU 的現代瀏覽器，推論時直接在顯卡上高速運算！

Q4: WebGPU 載入 3B 模型時閃退（exit code 1 / OOM）？

A: 顯存（VRAM）不足所致。解決方法：切換至較小的模型（推薦 Qwen2.5-0.5B 約 350MB），或關閉其他佔用 GPU 的應用程式後重試。若您的顯卡 VRAM 低於 4GB，建議改用 LM Studio / 後端 API 模式，將運算交給系統主記憶體處理。

Q5: LM Studio 回應時對話框空白但底部有 Token 統計？

A: 這是已知 DOM 節點脫離 Bug（v0.9.9 前舊版）。症狀：模型自動偵測到模型名稱時，舊版使用 innerHTML += 導致瀏覽器重建 DOM 並銷毀串流文字節點，回應全部寫入已脫離的無效節點，畫面空白但 token 統計有數值。此 Bug 已於 v1.0.0 修復，改用 insertBefore(badge, textBlock) 安全插入，串流渲染完整正常。請確保使用最新版本。

Q6: 切換語系（中↔英）後 AI 回應顯示 0 tokens？

A: 舊版切換語系時會插入語系提示詞至上下文（context），導致後端判斷 token 計算異常為 0。v1.0.0 已修復：語系切換僅更新 UI 顯示文字，不再汙染對話 context，AI 回應 token 統計完全正常。如仍遇到此問題，請點擊 「清除畫面」 重置對話後重試。
